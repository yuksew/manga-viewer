## コードが想定していること（照合の基準）

実データ側の確認は未了。以下はコードを読んで確認した想定。

- 冊として拾う拡張子は `zip` と `cbz` だけ（`src/book.rs:33` `is_zip_name`）。`cbr`・`rar`・`pdf`・`7z`・`cb7` は黙って無視され、一覧にもエラーにも出ない。
- 走査は root 直下から深さ 2 まで（`src/scan.rs:62`）。
  - 画像を直接含むフォルダは、深さ 1 以上のときだけ `folder` の冊になる。
  - ルート直下の zip は拾う。
- 画像の判定は拡張子（`IMAGE_EXTS`）で行う。
  - 壊れた画像の判定は、配信時に `src/imgcheck.rs` が PNG / JPEG / GIF / WebP の magic とヘッダ・終端を見る。
  - `IMAGE_EXTS` は png / jpg / jpeg / webp / gif の 5 つ（`src/book.rs:25`）。AVIF、BMP、TIFF は頁に数えられない。
- カードにある `src/image_check.rs` は存在しない。実体は `src/imgcheck.rs`。
- zip の中央目录は `zip` クレート経由で読まれる想定（`ZipArchive<File>`）。自前の magic 検査はしていない。
