## 4. 境界の叩き込み（使い捨て試験、commit しない）

- **`2 < 10`**: 冊の題名の並びも `Vol1, vol2, vol02, vol10`（大小無視・先頭ゼロが長い方が後）。
- **空 zip**: `NoPages`。`__MACOSX/` と `._` だけの zip も `NoPages`。
- **画像なしフォルダ**: 一覧に出ない。子フォルダにだけ画像がある場合は、その子が冊になる（親は出ない）。頁は直下のみで、子フォルダの画像は親の頁にならない。
- **ZIP とフォルダの混在**: 同じフォルダに画像と zip があれば 2 冊。
- **同名の冊が 2 階層に在る**: `x.zip`、`a/x.zip`、`b/x.cbz`、フォルダ `x`、`a/x` を置くと 5 件すべてが一覧に出る。重複で潰れない。並びは題名が同じなら path の順。
- **拡張子**: `UP.ZIP`・`.JpEg` など大文字も通る。`.bmp` は頁にならない。
- **ルート**: ルート直下の画像は冊にならない。存在しないルートは `Err`。

## 5. 所見（重い順の 3 件）

1. **ルート直下の画像を冊にしない規則に試験が無い（変異 5 が生き残り）。**
   実装は `depth > 0` で外しているが、設計 A-3 は「ルート自身」の扱いを書いていない。実装記録には書いてあるが、試験が無いので将来の改修で黙って変わる。
   直し方: ルート直下に画像を置いて冊に出ないことを確かめる試験を足し、設計 A-3 に一文足す。
2. **ルート直下の zip／cbz を冊にしている（設計に無い判断）。**
   実装記録の「設計から外れた点」3 に申告済みで、結合試験（`loose.cbz`）も固定している。ただし設計本文が決めていないので、設計側で追認するか、取り消すかを決める必要がある。放置すると p0-1b の突き合わせとずれる。
3. **題名は一意でない。** 同名の冊が 5 件共存するので、p0-1b の索引と p0-3 の一覧は題名を鍵にできない。鍵は path（設計 §2.2 の「冊の鍵」）でなければならない。1b の試験に同名 2 冊を入れること。

## 6. その他（軽微・未確認）

- 暗号化 zip（`Encrypted`）と非 UTF-8 の zip エントリには試験が無い。合成が難しいため実装記録でも未検査と申告されている。分岐のコードは読んで確認しただけ。
- `read_page_bytes` は `Vec::with_capacity(entry.size())` を使う。ヘッダの大きさ表記が偽の zip で巨大確保になりうるか、は**試していない**。p0-2a の画素数上限と併せて見る。
- フォルダ冊の `mtime_ns` はフォルダ自身の更新時刻。中の画像を同名で上書きしても動かない可能性がある。1b の「更新」検出で、`size`（直下の画像の合計）と合わせて足りるかを見る。
- Windows で `to_string_lossy` を通した名前は、不正な UTF-16 名のファイルだと `read_page_bytes` で開けなくなりうる（試していない）。
- `docs/project-guide.md` は branch を `main` と書くが実際は `master`。
- 作業ディレクトリ `C:\work\manga-viewer` と `F:\work\manga-viewer` は同じ git リポジトリ（HEAD 一致）を指していた。
