## 判定: **直してから**

挙動は CLI の実走で設計どおりに動いた。しかし (1) 設計 §5 の p0-2a（デコード）が存在せず、
(2) 実装された索引の永続化には**差分索引・削除整理・順序を守る試験が 1 本もない**。変異 5 本すべてが検出されなかった。

## 最も重大な 3 件

1. **索引 DB の試験が無い（変異 5/5 未検出）。** `src/index.rs` の単体 6 本は純関数（`path_key` / `under_root` / `absolute` / 往復 / `rescanned` / DB パス）だけで、
   `reindex` / `books` / `Index::open` を呼ぶ試験が無い。結合試験 7 本も p0-1a のもの（`cli_index_summarizes` が `books=` 行を見るのみ）。
   設計 §5 の p0-1b 欄が求める「初回→件数一致、2 回目は再スキャン 0、追加/削除/更新の反映、broken が status に残る、`user_version` 破壊で作り直し」は未実装。
   変異（いずれも `cargo test` が通った）:
   | 変異 | 結果 |
   | --- | --- |
   | 差分判定を常に真（`\|\| true`、永久に再スキャンしない） | 未検出 |
   | 差分判定を常に偽（毎回再スキャン） | 未検出 |
   | 削除の整理を無効化（`if limit.is_none()` → `if false`） | 未検出 |
   | 削除範囲 `under_root` を外す（別ルートの行も巻く） | 未検出 |
   | `books()` の自然順ソートを外す | 未検出 |
   実装記録の「単体 10 + 結合 7 で合格」は、これらの挙動が守られている根拠にならない。
2. **カードの段（p0-2a = `decode` モジュール）が未実装で、記録も別名。** 設計 §5 の p0-2a は「バイト → 画像、縮小 RGBA、サムネイル JPEG、`Limits`、破損は Err」だが `src/decode.rs` は無い。
   実際に入ったのは設計 p0-1b 相当の索引永続化で、実装記録は `docs/p0-2b-implementation.md`（`p0-2a-implementation.md` は存在しない）、commit も `p0-2b:` と名乗る。
   設計の段名（p0-2b = 頁キャッシュ + 先読み）と食い違うので、後続カードの取り違えを招く。段の呼称を直し、decode は別途着手が要る。
3. **壊れた DB ファイルで回復しない。** 中身が不正（`garbage` 700 B）の `index.db` は `file is not a database` で終了コード 1 になり、`index` も `list` も続行できない。
   設計は `user_version` 不一致のみ作り直すと書くが、「作り直せる物だけを入れる」方針なら不正ファイルも捨てて作り直すのが自然。0 バイトのファイルは通る（空 DB 扱い）。利用者が手で DB を消すしかない。

## 軽い所見

- `index` の `root=` / `db=` 行に `\` と `/` が混ざる（`...\aud/root`）。表示のみ。
- `list` は DB 全体を出す（ルートで絞らない）。複数ルートの DB では混ざる。`books_under` は lib にあるが CLI から使えない。
- フォルダ冊の鍵の弱さ（同サイズ差し替えを検出しない）は設計 §7-8 で許容済み。
- 頁数は ZIP エントリ名の数で、画像が実際にデコードできるかは見ない（decode 段の仕事）。

1. `reindex` の試験を足す（合成データを `tests/common` で作り、上の変異 5 本がすべて落ちること）。

3. 不正な DB ファイルは作り直す（または明確な案内文で終了する）。
