# manga-viewer

zip / フォルダの漫画を、ブラウザなしの単独ウィンドウで読むビューア（Windows）。exe は 1 つで、外部ランタイムも要らない。

## 一覧から読む

`manga-viewer`（引数なし）で起動すると、索引 DB に冊があれば冊の一覧（表紙グリッド）が出る。表紙が無い冊の表紙は裏で作り、できた順に出る。`--root <dir>` でその下の冊だけに絞れる。索引 DB が無いか空なら、従来どおり zip / フォルダのドロップを待つ空の窓になる。

- 矢印キーで選択（↑/↓ は 1 行、PageUp/PageDown は 3 行）、Home/End で先頭/末尾、Enter かダブルクリックで開く。
- 壊れた冊は×印・赤字。開こうとすると理由を上部に出す。
- 読んでいる途中の Esc で一覧へ戻る（スクロール位置はそのまま、読んでいた冊が選ばれる）。一覧での Esc で終了。

## 使い方（2 コマンドで完結）

```
manga-viewer index <root>                 # root 以下を走査して索引 DB に登録する
manga-viewer view --book <id> [--page N]  # 索引の冊を単独ウィンドウで開く
```

1. `index <root>` で冊を索引する（既定の root は `D:\books`）。索引 DB は既定で `%LOCALAPPDATA%\manga-viewer\index.db`。`--db <path>` か環境変数 `MANGA_VIEWER_DATA` で変えられる。権限などで読めなかったフォルダは飛ばして続け、要約行の `skipped=N` と標準エラーの `skipped	<path>	<理由>` で知らせる（その下の登録済みの冊は消さずに残す）。
   `index <root> --thumbs` で、表紙が無い冊の表紙サムネイル（先頭頁を 240×340 以内に縮小した JPEG）も作って DB に入れる。2 回目以降は新しい冊・中身が変わった冊の分だけ作る。
2. `list` で冊の id を確かめる（TSV: id / title / kind / page_count / status / path）。
3. `view --book <id>` で開く。`--book` を省略すると最初の壊れていない冊を開く。`--page N` は 0 始まりで、頁数以上なら最後の頁に丸める。
4. 操作:
   - 頁送り: →/PageDown/Space/マウスホイール下で次、←/PageUp/ホイール上で前（ホイールは 1 イベント ±1 頁。キーと同時でも二重に進まない）。
   - `F` で単頁⇔見開き 2 頁（右綴じ：右が若い頁、左が次の頁）。1 枚目は表紙として 1 枚で出し、以降は 2-3, 4-5… の組で並べる（相手の無い最終頁も 1 枚）。並べた 2 頁は窓の中央で隙間なく接する。見開き中は送りが 1 組ずつ。窓幅が 700 未満のときは自動で単頁。今のモードは窓の上端にカーソルを当てたときに出る帯の `[単頁…]` / `[見開き…]` に出る（窓が狭くて見開きにできないときはその理由と幅も出る）。IME 等で F がキーとして届かずテキストで届く場合も拾う。
   - 上部の表示: 頁番号とモード（全画面では冊名も）は、窓の上端にカーソルを当てている間だけ頁の上に重ねて出す。普段は頁だけで、頁は窓いっぱいに使う。「次の冊はありません」などの通知はカーソルに関係なく上部に出る。
   - 頁スライダー: 窓の下端にカーソルを当てている間だけ、下に頁スライダーが出る（右綴じなので右端が 1 頁目）。つまんで動かす間は行き先の頁番号を出し、離すとその頁へ飛ぶ。トラックのクリックはその場で飛ぶ。スライダーの上では窓のドラッグ移動はしない。
   - 全画面: F11 か頁の上のダブルクリックで全画面 ⇔ 窓（F11 は一覧でも効く）。全画面中の Esc は全画面を解くだけ（一覧へ戻る・閉じるは窓のときだけ）。全画面中は上部の表示に冊名も出す。スライダーと次冊の確認の上のダブルクリックは対象外。
   - 先読み: 表示中の次/前の頁を裏スレッドで先に復号し、頁番号ごとにキャッシュする（F の切替や戻りで再復号しない）。各頁の復号・テクスチャ変換時間は標準エラーに `page …` 行で出る。`cargo run`（dev）でも依存クレートは最適化ビルドにしてある（これが無いと 1 頁の復号が約 50 倍遅かった）。
   - 最終頁で「次」をすると、窓の中央に「次の冊を開きますか？」の確認が浮かんで出る（背景は暗くなる）。Enter か「はい」ボタンで次の冊、Esc か「いいえ」で閉じる（見開き中は今の組に最終頁が入っているとき）。最初の頁で「前」をすると同様に前の冊の確認が出る。確認と逆向きにホイールすると（次の冊の確認なら上、前の冊の確認なら下）確認は閉じて今の頁のまま。確認中はそれ以外の送り入力（キー・同じ向きのホイール）を無視する。
   - 次冊/前冊は、`view` を索引から開いていれば索引の順（壊れた冊は飛ばす）、`--path` やドロップで開いていれば同じフォルダ内の自然順（zip/cbz と画像フォルダ）。候補が無ければ窓内に表示して現在の冊のまま。
   - ドラッグ移動: タイトルバー以外（画像の上を含む窓のどこでも）を左ボタンで押したまま動かすと窓ごと移動する（約 6 点動かすと移動開始）。移動中はキー/ホイールの頁送りは無視し、離すと元に戻る。ボタン（はい/いいえ）の上からは移動しない。全画面中は移動しない。ホイール送りは移動していないときは今までどおり。
   - 窓の大きさ・位置・最大化/全画面と見開きの状態は、閉じたときに保存して次の起動で戻す（索引 DB と同じフォルダの `window.ron`）。モニター構成が変わって画面外になる位置は今のモニターへ寄せる。`MV_PERSIST=0` で持ち越さない（`MV_TRACE`・`--autopilot`・`--exit-after-ms` の窓も持ち越さない）。
   - Esc で終了（一覧から開いたときは一覧へ戻る）。

zip/cbz 内のファイル名は UTF-8 で読み、UTF-8 でない古い zip は CP932（Shift_JIS）として読む（頁名が化けず、自然順の並びも保たれる）。

ビルドは `cargo build --release`。成果物は `target/release/manga-viewer.exe` 1 つだけで、そのまま配れる。

## 壊れた画像

画像が壊れていても読み続けられるように、view は復号に失敗した頁を自動で修復する（終端マーカーで切る、末尾が欠けた分は部分復号する）。修復した頁には、画面に注記（「途中で切れて…」など）を出す。修復できない頁は「この頁は表示できません」と出し、ほかの頁はそのまま読める。

## 速さを測る

- `MV_TRACE=1` を付けて引数なしで起動すると、起動 → 一覧の初回描画（`trace	startup_list_ms`）、冊を開く → 表紙の仮表示 / 1 頁目（`open_placeholder_ms` / `open_page_ms`）、頁送り → その頁が描かれる（`turn_ms`）を標準エラーに 1 行ずつ出す。閉じるときに名前ごとの件数・p95・max と、そのときのメモリ（`rss_mb`）を出す。時間は GPU への転送を含むフレームの終わりまで（画面への反映は DWM が次の vblank で行う）。
  ```
  $env:MV_TRACE=1; manga-viewer 2> trace.txt
  ```
- `--autopilot startup|reader --db <path> --root <dir>` は、実際の窓でキー入力を自動で送って場面を再現し、`BENCH` 行を標準出力に出して閉じる（`startup`: 起動 → 一覧・表紙、`reader`: その後に先頭の冊を開き、100 ms 間隔で 100 頁、続けて毎フレーム 60 頁送る）。実データを読まないよう `--db` の指定が要る。合成 724 冊での通しは `cargo test --release --test perf_lines real_window -- --ignored --nocapture`。
- 垂直同期（vsync）は既定で切っている（有りだと描画が 1 フレームごとに 31〜46 ms 待たされ、冊を開いて 1 頁目まで 96 ms かかった。切ると 24 ms）。`MV_VSYNC=1` で戻せる。
